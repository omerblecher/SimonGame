Generate the release keystore and harden .gitignore files to prevent credentials and secrets from being committed to git.

Purpose: The keystore is the cryptographic identity of the app — losing it means the app can never be updated on the Play Store. The .gitignore changes ensure *.jks, keystore.properties, and .env.production can never be accidentally committed.

Output: simon-release.jks at C:/Users/omerb/keystores/, root .gitignore and android/.gitignore updated with all secret-file patterns.

Note on META-01/02/03: These are already satisfied in the codebase. This plan verifies them with grep commands as part of the pre-build confirmation checklist.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local filesystem → git staging | Secret files (*.jks, keystore.properties, .env.production) must never cross this boundary |
| Keystores directory → project directory | Keystore is stored at C:/Users/omerb/keystores/ (outside repo) to eliminate risk even if .gitignore is misconfigured |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | simon-release.jks | mitigate | Store outside repo at C:/Users/omerb/keystores/; *.jks in both root and android/.gitignore |
| T-04-02 | Information Disclosure | android/keystore.properties (passwords) | mitigate | keystore.properties in both .gitignore files; not created until Plan 04-05 |
| T-04-03 | Information Disclosure | .env.production (production AdMob ID) | mitigate | .env.production in root .gitignore; file not created until Plan 04-05 |
| T-04-04 | Denial of Service | Keystore loss | mitigate | Backup to 2 locations (local Documents + cloud private folder); Play App Signing means upload key can be reset |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase |
</threat_model>
